# Версионирование

Проект использует [Semantic Versioning](https://semver.org/lang/ru/) **без
префикса `v`**.

Тег релиза выглядит так:

```
0.1.0
0.2.0
1.0.0-rc.1
```

и **не** так:

```
v0.1.0
```

## Как это устроено

- Workflow релиза (`.github/workflows/release.yml`) срабатывает на теги,
  начинающиеся с цифры. Тег с `v` его не запустит.
- Тег — единственный источник версии: workflow передаёт её в Gradle через
  `-PversionName`, оттуда она попадает и в манифест APK, и в имя файла
  (`sesame-0.2.0.apk`). Версия в `build.gradle.kts` — только локальный фолбэк
  для сборки без тега.
- Формат тега проверяется в workflow. Тег, не являющийся semver, валит сборку
  с внятной ошибкой, а не выкладывает релиз со странным именем.
- `versionCode` выводится **из самой версии**: `major * 1_000_000 + minor * 1_000
  + patch`. `0.2.0` даёт `2000`, `1.4.2` даёт `1004002`. Растёт монотонно вместе
  с semver, оставляет по 999 значений на minor и patch и не переполняет `Int`.
  Суффикс предрелиза (`0.3.0-rc.1`) на код не влияет — он метка, а не порядок.

  Раньше код брался из номера прогона workflow. Это выглядело проще, но номер
  прогона с версией никак не связан: локальные сборки и сборки из CI получали
  несопоставимые коды, и APK из релиза мог отказаться ставиться поверх уже
  установленного. Пересоздание репозитория или сброс счётчика ломали бы это так
  же.

## Выпуск релиза

```bash
git tag -a 0.2.0 -m "описание изменений"
git push origin 0.2.0
```

## Историческое исключение

Первый релиз был выложен под тегом `v0.1.0` — до того, как соглашение было
принято. Он оставлен как есть: удаление опубликованного релиза ломает ссылки, а
пользы от переименования нет. Все последующие теги — без `v`.
